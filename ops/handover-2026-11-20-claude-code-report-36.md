## Part 3. Findings and options (no change)
1. Can code log agent-to-agent sends with from, to, time, run ID? YES, with after_tool_call (observe-only) matched to sessions_send: from = ctx.agentId, to = agent id parsed from params.sessionKey (agent:<id>:...), time = handler time, run ID = regex coo-\d{8}-\d{4} on params.message (record only the token, never the text; null if absent), type = a fixed word like send. Caveat: the run ID depends on the COO writing it into the message (it does under v1.10.9, seen in the probe); sends without it get "none".
2. CEO direct messages in an agent's own channel: YES for Slack via message_received (what ceo-ledger already does: hash, no text). Not provable in scratch (no Slack); ceo-ledger is the existing proof. A direct `openclaw agent` CLI message gives no hook.
3. Needed: a new hook-only, observe-only plugin (own folder under ~/loop1/state/extensions, manifest like ceo-ledger, no conversation access), enabled in plugins.entries (one config key), gateway restart (time window and a separate APR), plugin hash lines in the health check (like ceo-ledger and gate-plugin), unit tests with a fake api.
4. Minimum COO change: let the COO READ one file written by the plugin, workspace-only. Cleanest: the plugin writes a log file inside the COO workspace (for example state/send-log.md) and the COO gets the read tool restricted by tools.fs.workspaceOnly=true (the CHO config already has fs.workspaceOnly + alsoAllow read). Keys involved: agents.entries.coo.tools.fs.workspaceOnly and tools.alsoAllow (read), plus plugins.entries.<new>.enabled. NOT YET KNOWN: whether adding alsoAllow:["read"] to the COO changes other COO behaviour (it may then answer from files it should not); needs a scratch test.
5. Risks: after_tool_call handlers are fire-and-forget and errors are logged, so a slow or failing handler does not block a send; use only after_tool_call (never before_tool_call, which fails closed), wrap the write in try/catch, use appendFileSync, bounded size. Events can overlap; lines may interleave (one append per event is atomic enough). Writes inside the gateway process use the gateway's user permissions.
6. Already-tested flows that could be affected: the COO routing and run-ID flow (H32/H33/H34), CFO logging, ceo-ledger and gate-plugin shadow gate (a third plugin loading), gateway startup time. Proof: the scratch routing test (Part 2 scenario 1) with the plugin loaded in scratch compared with without it, the unit suite, health check with the new hash lines, and a regression run only when the CEO allows one.
NOT YET KNOWN: Slack channel behaviour of message_received in a thread; whether sessions_send also fires hooks when the CFO session is in a Slack channel (the COO sends to the main session, shown here); the text of the first sessions_send error; behaviour under gateway restart (lines lost during shutdown).
