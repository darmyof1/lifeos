## Part 1. Build in ~work37 (repo files, unwired until Part 3)
Put the plugin in deploy/after-loop7/send-log-plugin/ (openclaw.plugin.json id send-log with an empty config schema and activation.onStartup like ceo-ledger, package.json, index.js, log.js with no OpenClaw imports so it tests away from the gateway, tests/, design.md of one page). Behaviour (exactly as in the approved design):
- Hook after_tool_call, only when event.toolName is sessions_send: write one line with fields in this order, separated by " | ": time (America/Puerto_Rico, "YYYY-MM-DD HH:MM"), the word "send", "<from> -> <to>" (from = ctx.agentId; to = the agent id parsed from params.sessionKey agent:<id>:..., else "unknown"), run ID (the first token matching coo-\d{8}-\d{4} in params.message, else "none"; the token only, never the text), result "ok" or "error". On error add " | " and the masked error text.
- Masked error text: take event.error, collapse whitespace and newlines to single spaces, replace session keys (agent:...), any run of 9 or more letters and digits mixed with a digit, any 6 or more digits, and anything that looks like a token, with "<id>"; cut to 80 characters. If the masked text contains any substring of 20 characters taken from params.message, write only "error (text withheld)". Never write params.message or event.result.
- Hook message_received: only when the sender id equals the CEO id read from ~/loop1/ceo-slack-id (same reading code and same fail-safe as ceo-ledger: no file or empty file means write nothing). Line: time | "ceo-message" | "<agent> channel" (the agent id of the Slack account that received it, the same account field the ledger uses; map the account name to the agent id; if unknown write "unknown channel") | first 8 hex of sha256 of the text. No text.
- Log file: ~/loop1/workspaces/coo/state/send-log-YYYY-MM.md (month in AST), created with one header line "# send log (written by code, no message text) - YYYY-MM" the first time. Append-only; never rewritten; the gateway user's permissions only. Failure to write is swallowed and counted in memory; no exception reaches the gateway.
- Unit tests (node and/or python as ceo-plugin does): only the two hooks registered and no other register call; before_tool_call never registered; a sessions_send event produces the exact line; a non-sessions_send tool produces nothing; run ID token found, and "none" when absent; target parsing; masked error text (session key, long ids, digits masked; 80 cut; withheld rule); no message text in any line (assert with a distinctive synthetic text); ceo-message line only for the CEO id, none for others or an empty id file; write failure swallowed; header written once; month rollover; handler returns undefined. Strict suite `python -X dev -W error -m unittest discover -p "test_*.py"` and the validator must pass.
- Update deploy/loop1/health-check.py and its tests: new send-log plugin hash lines (index.js, log.js, manifest, package.json equal to the repo copy) and one line "plugin send-log enabled, hook-only", in the same style as ceo-ledger and gate-plugin; the "no conversation access" check (the config entry has no hooks key). Do NOT change the COO tool line (the COO still has no file tools after this handover).
